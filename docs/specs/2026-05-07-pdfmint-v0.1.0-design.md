# pdfmint v0.1.0 設計

**Date:** 2026-05-07
**Project:** `@hayashiii/pdfmint`
**Repository:** `hayashiii-ghub/pdfmint`

## 目的

HTML / Markdown ファイルを綺麗な PDF に変換する **AIエージェントファースト** な CLI ツール。AIエージェント（Claude Code, Codex等）がHTMLを生成し、それを `pdfmint` で PDF化する流れを想定。

## 動機

- AIエージェントが HTML/CSS で凝ったデザインを生成できる時代になった
- 生成された HTML を PDF化する **AIフレンドリーな標準ツール** が個人開発者層に欠けている
- `@hayashiii/sitesnap`（Webサイト→スクリーンショット）と並べた **CLIツールシリーズ** としてポートフォリオ化する
- 開発者自身（人間）も日常使い（請求書・履歴書PDF化）できる必要あり

## スコープ

### 含む（v0.1.0）

- HTML ファイル → PDF 変換
- Markdown ファイル → PDF 変換（`marked` で HTML 化を経由）
- バッチ処理（glob パターンで複数ファイル一括）
- `--json` 構造化出力（成功・失敗・パス情報）
- 構造化エラー（`code` + `message` + `hint` + `context`）
- AGENTS.md（AIエージェント向け仕様書）
- Claude Code Skill 同梱（`skills/pdfmint/SKILL.md`）
- README.md（日本語）+ README.en.md（英語）
- CHANGELOG.md
- LICENSE (MIT)
- テストスイート（`bun test`）
- 既存 `hayashigoto-assets/invoices/pdf-tool/` からの移行手順

### 含まない（v0.2.0 以降）

- QRコード自動埋め込み（v0.2.0）
- 設定ファイル（`.pdfmintrc.json`）（v0.3.0）
- カスタムCSS外部指定（v0.3.0）
- マルチブラウザ対応（PDF生成にはChromeで十分なため検討対象外）
- リアルタイムプレビュー
- GUI

### 含まない（恒久的に）

- HTML作成テンプレート同梱（AIエージェントが直接HTML生成する想定のため不要）
- WYSIWYG編集機能

### モジュール責務

| ファイル | 責務 | 公開関数 |
|---|---|---|
| `cli.ts` | エントリ・引数解析・ルーティング | `main()`（実行のみ） |
| `convert.ts` | 単一HTML→PDF変換 | `convertHtmlToPdf(input, output, options)` |

各モジュールは小さく、一つの責務に集中。テストもファイル単位で独立。

## CLI仕様

### コマンド一覧

| コマンド | 用途 | 例 |
|---|---|---|
| `pdfmint <input> <output>` | 単一変換（最短形式） | `pdfmint invoice.html invoice.pdf` |
| `pdfmint batch <pattern> <out-dir>` | バッチ変換 | `pdfmint batch "./html/*.html" ./pdf/` |
| `pdfmint help` | ヘルプ表示 | `pdfmint help` |
| `pdfmint --version` | バージョン表示 | `pdfmint --version` |

### 入力フォーマット自動判別

| 拡張子 | 処理 |
|---|---|
| `.html` | HTML として扱う、Puppeteer で直接レンダリング |
| `.md` / `.markdown` | Markdown として扱う、`marked` で HTML に変換してからPDF化 |
| その他 | エラー（`UNSUPPORTED_INPUT`） |

### グローバルフラグ（全コマンド共通）

| フラグ | デフォルト | 説明 |
|---|---|---|
| `--json` | off | 結果を JSON 形式で stdout に出力 |
| `--format <size>` | A4 | 用紙サイズ（A4 / A3 / Letter / Legal） |
| `--margin <value>` | 0 | 余白（CSS の `@page` 優先、指定するとoverride） |
| `--landscape` | off | 横向き |
| `--no-background` | off | CSS背景色・画像を無効化（デフォルトは有効） |

### JSON出力フォーマット

#### 成功時（単一変換）
```json
{
  "success": true,
  "input": "/abs/path/invoice.html",
  "output": "/abs/path/invoice.pdf",
  "format": "A4",
  "size_bytes": 4827410,
  "duration_ms": 1234
}
```

#### 成功時（バッチ）
```json
{
  "success": true,
  "total": 10,
  "succeeded": 9,
  "failed": 1,
  "results": [
    { "input": "...", "output": "...", "size_bytes": 1234, "duration_ms": 1234 }
  ],
  "errors": [
    { "input": "...", "code": "...", "message": "..." }
  ]
}
```

#### 失敗時
```json
{
  "success": false,
  "error": {
    "code": "INPUT_NOT_FOUND",
    "message": "入力ファイルが見つかりません: invoice.html",
    "hint": "ファイルパスを確認してください",
    "input": "invoice.html"
  }
}
```

### エラーコード一覧

| コード | 状況 |
|---|---|
| `INPUT_NOT_FOUND` | 入力ファイルが存在しない |
| `INPUT_NOT_READABLE` | 入力ファイルが読めない（権限） |
| `UNSUPPORTED_INPUT` | 未対応の拡張子 |
| `OUTPUT_DIR_NOT_FOUND` | 出力先ディレクトリが存在しない |
| `OUTPUT_NOT_WRITABLE` | 出力先に書き込めない |
| `BROWSER_LAUNCH_FAILED` | Chromium 起動失敗 |
| `PAGE_LOAD_FAILED` | ページロード失敗（タイムアウト等） |
| `PDF_GENERATION_FAILED` | PDF生成中のエラー |
| `BATCH_NO_MATCHES` | バッチパターンにマッチするファイルなし |

### 終了コード

| コード | 意味 |
|---|---|
| 0 | 成功 |
| 1 | 一般エラー（処理失敗） |
| 2 | 引数エラー（不正な引数、ヘルプ表示時など） |

### 3. 構造化エラー

#### TypeScript の型定義（`src/errors.ts`）

```typescript
export type ErrorCode =
  | "INPUT_NOT_FOUND"
  | "INPUT_NOT_READABLE"
  | "UNSUPPORTED_INPUT"
  | "OUTPUT_DIR_NOT_FOUND"
  | "OUTPUT_NOT_WRITABLE"
  | "BROWSER_LAUNCH_FAILED"
  | "PAGE_LOAD_FAILED"
  | "PDF_GENERATION_FAILED"
  | "BATCH_NO_MATCHES"

export interface ErrorContext {
  input?: string
  output?: string
  pattern?: string
}

export class PdfMintError extends Error {
  code: ErrorCode
  hint: string
  context: ErrorContext

  constructor(code: ErrorCode, message: string, hint: string, context: ErrorContext = {}) {
    super(message)
    this.code = code
    this.hint = hint
    this.context = context
  }

  toJSON() {
    return {
      code: this.code,
      message: this.message,
      hint: this.hint,
      ...this.context,
    }
  }
}
```

#### エラーメッセージの設計指針

各エラーは以下を必ず含む:
- **`code`**: AIエージェントが分岐に使える機械可読な定数
- **`message`**: 人間が読む説明
- **`hint`**: AIエージェントが**次に何をすべきか**を判断できるヒント
- **`context`**: 失敗対象のファイルパス等

### 4. `--json` 出力の設計指針

| 観点 | 仕様 |
|---|---|
| 出力先 | **stdout**（stderrではない、エージェントがパースしやすいように） |
| エラー時 | **stdout に JSON、終了コード 1**（パースしてからエラー判別できるように） |
| 通常出力との混在 | `--json` 指定時は stdoutにはJSONのみ、進行ログは stderr に出力（パース邪魔しない） |
| 成功時 stderr | 空（または指定があれば進行ログ） |
| ストリーミング | バッチ処理でも **最後に1回まとめてJSON出力**（途中経過は不要、シンプルに） |

### 5. AIエージェント体験の最適化

#### コマンドの「予測可能性」
- 引数2つ：`pdfmint <in> <out>`
- バッチは1つのサブコマンド：`pdfmint batch <pattern> <out-dir>`
- フラグは長い形式のみ（`--json`、短縮形は提供しない）

#### 副作用の明示性
- ファイルを上書きする際、デフォルトで上書き許可（CIや自動化前提）
- 出力先ディレクトリが存在しない場合は **作成しない**（明示的にユーザーが作る、誤操作防止）

## 開発・配布

### 開発環境セットアップ

```bash
git clone https://github.com/hayashiii-ghub/pdfmint.git
cd pdfmint
bun install
bun src/cli.ts ../sample.html ./out.pdf  # TypeScript直接実行
bun test
```

### ビルド構成

`package.json` の scripts:

```json
{
  "scripts": {
    "build": "bun build src/cli.ts --target=node --format=esm --outfile=dist/cli.js --banner=\"#!/usr/bin/env node\"",
    "test": "bun test",
    "typecheck": "tsc --noEmit",
    "prepublishOnly": "bun run typecheck && bun test && bun run build"
  }
}
```

ポイント:
- `--target=node`: Node.js 互換のJSへバンドル
- `--format=esm`: ESM出力
- `--banner`: shebang を bundle 先頭に挿入
- `prepublishOnly`: publish前にtypecheck + test + buildが自動実行
